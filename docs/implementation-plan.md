# GLead implementation plan

**Date:** 22 Oct 2026 · **Inputs:** `prd-concise.md` v1.1, `research/R1-codebase-audit.md`, `research/R3-licences.md`. R2 (mic feasibility on real devices) and R4/R5 are still open and are scheduled below; nothing in Sprints 0–1 waits on them.

## 1. Starting point

**A new repository, `franxh090/GLead`, with FretFree's pure modules vendored in.** Not a fork. R1 §1 gives the reasons: FretFree is now a 70k-line app moving at 16 work packages a day, GLead's P0 drills are all new, and the modules GLead needs (theory, mic, audio, fretboard, FSRS grading/scheduler/adaptive) import nothing else and pass their tests inside GLead unchanged. The copy is pinned to commit `f523388` and documented in `src/vendor/fretfree/UPSTREAM.md`; MIT notices are in `THIRD_PARTY_NOTICES.md` (R3). OpenEar's exercise designs and cadence recipe, and FretEcho's mute-while-prompting protocol and weak-spot weighting, are re-implemented rather than copied.

## 2. Architecture

```
src/
  vendor/fretfree/     reused (MIT): theory, mic, audio, fretboard, engine core
  core/                GLead's engine (pure TS, no React)
    types.ts           InputAdapter, Drill, Scorer, BackingLoop, TrialEvent, Item, Card
    input/             tap adapter; mic adapter over PitchSource with confidence + confirm
    events/            Dexie trial log, JSON export, metric queries
    scheduling/        cards (FSRS via vendored scheduler), interleaving across skills
                       and keys, retest schedule (1/7/30 days, unseen keys), key rotation
    session/           runner: plan → prompt → listen → grade → log → feedback
  audio/               cadence, backing loop (key, progression, tempo, feel) on vendored audio
  drills/              one folder per drill; logic.ts pure + tested, view .tsx
  screens/             Today, Session, Progress, Settings
```

## 3. Interfaces to define first (Sprint 0)

- **`InputAdapter`**: `start()`, `stop()`, `onAnswer(listener)`, `state`. Emits `InputEvent { kind: 'play' | 'tap'; midi?: number; degree?: number; position?: Position; confidence: number; at: number }`. The tap adapter has confidence 1. The mic adapter wraps `PitchSource`: a stable note becomes a `play` event with confidence from clarity and cents; below `confirmBelow` the session asks the learner to confirm by tap.
- **`Drill<P, A>`**: `id`, `title`, `skills`, `inputModes`, `requiresMic`, `makePrompt(item, ctx)`, `prompt(p): AudioScript` (what to play, in order), `check(p, a): Check`, `describeAnswer(a)`, `feedbackPositions(p, fb)`, `rationale` (one line, D5), `render`. Same shape as FretFree's `DrillType` so drills can move either way.
- **`Scorer`**: for play-along (C2): `start(loop)`, `onNote(note)`, `result(): BarHits[]` (per chord change: on a chord tone within the window, which tone, or miss).
- **`BackingLoop`**: `{ key, progression, bpm, feel, bars }` → `start({ onChord })`, `stop()`; built on `playProgression(loop: true)`.
- **`TrialEvent`**: `trialId, sessionId, at, drillId, itemId, skillId, key, mode (play|tap|confirm), correct, expected, given, responseMs, confidence, imagineFirst, feedbackVariant, experimentArm, retest (none|1d|7d|30d), unseenKey`. Append-only; everything on the dashboard is a query over it (R5 will refine the formulas).

## 4. Sprint plan (two-week sprints)

- **Sprint 0: foundations.** ✔ Done 2026-10-22: repo, vendored modules, build green, licences recorded; `core/types.ts`; Dexie trial log with export; tap adapter; cadence, script player and backing-loop generator; the session runner; Today, Session, Progress and Settings screens.
- **Sprint 1: B1 end to end.** ✔ Built 2026-10-22, pending the human check: mic adapter with confidence and tap-to-confirm (threshold 0.6, provisional until R2); B1 "scale degree in key": cadence → target → play or tap → feedback on the neck → FSRS card per degree and mode; keys rotate every trial; imagine-first option (B6); five Playwright specs through the fake mic. **Still to do by a person:** a 10-minute B1 session on a laptop with a real guitar, then on a phone, and the R2 harness (`Settings → Test the microphone` shows the confidence per note).
- **Sprint 2: hearing the key.** ✔ Built 2026-10-23: B3 note against chord (triads, then sevenths); B2 chord function (I IV V vi, then ii iii vii°, then minor), answered by numeral or by playing the root; B7 interleaving across skills (new items dealt by turns, runs of one skill broken up); C3 backing loops for the five PRD progressions in any key, with the sounding chord's tones on the neck (the Loops screen). **Not done:** R2 thresholds, which need a person with a guitar and a phone; the confirm threshold stays at 0.6.
- **Sprint 3: using it.** ✔ Built 2026-10-23: C1 chord-tone ladder (roots → 3rds → 5ths and 7ths → any) with targets on the neck and a switch to hide them; C2 scoring of the first note in a one-beat window after each change, through the mic or by neck tap, with a hit map and every change logged as a trial; D1 placement test (22 trials over B1 major, B2 primary, B3 triads, B1 minor; no retries or card updates; skills at 75% seeded as known); D3 retests scheduled at 1, 7 and 30 days when a skill first reaches 90% over 20 practice trials, run in unseen keys from Today. **Still provisional:** the one-beat scoring window and 150 ms anticipation allowance, until R2 measures mic latency on real devices; targets fade by a switch, not yet by accuracy.
- **Sprint 4: keeping it.** ✔ Built 2026-10-23: D4 dashboard (per-skill report with baseline, trials, recent accuracy, trials to criterion, learning rate, retests and transfer; experiment arms compared); the §6 experiment harness (arms dealt once per learner, imagine-first and feedback variant drawn per trial and logged); D2 session shape (goal stated up front, reviews first, then new items, then a play-along handed to Changes with the rung chosen from the session's skills); D5 (rationale on every drill, reflection prompt, last reflection shown on Today); B4 melodies by ear (sequence answers through the runner); B5 spot the error (wrong chord or wrong note); `research/R5-measurement.md` (schema, formulas, pilot protocol, consent note). **Decisions waiting on Frank:** R5 §6.
- **Sprints 5–6: pilot.** Sprint 5 ✔ built 2026-10-24: the Keys screen (A1 scale and chords on the neck with sound on tap; A2 each chord in three CAGED zones); the R5 measurement fixes (a skill rests while its retest is pending; interleaved and blocked practice alternate by week under the `schedule` arm and are recorded per trial; Changes targets fade once two takes land 80%); the pilot kit (`docs/pilot-kit.md`, an export viewer on Progress, `docs/teacher-interview-guide.md`). **Sprint 6** (the pilot itself is people's work: 5–10 players for 4 weeks per R5 §4, the teacher interviews, then fixes from both) ✔ built 2026-10-24 on the software side: the Mic lab in Settings runs the R2 protocol on the learner's own device and saves the run with the export (24 notes, 8 wrong notes, 12 clicks; accept rates, confirm share, median latency, a suggested confirm threshold the learner can adopt in one tap); A4 in Keys (circle neighbours, capo helper, six why-it-works cards heard before read); the D7 weekly goal that counts sessions and never changes the schedule. **Sprint 7** ✔ built 2026-10-24: Spanish through an i18n layer with English fallback (navigation, Today, Session, Settings, the drill views and shared parts, Progress and Keys headings; the browser's language on first run); alternate tunings from Settings through the runner, every neck, the key map and the Mic lab (FretFree offers standard and drop D; CAGED zones stay standard-tuning only); B8 intervals by ear with song hints, and Find my key from a played phrase (Krumhansl–Kessler profiles). **Remaining P1 after Sprint 7:** C4, more tunings, the rest of the Spanish.
- **Sprint 8** ✔ built 2026-10-24: C4 call and response (after a B4 melody is copied, the call plays once more and the learner answers with a phrase of their own, through the mic or on the neck, up to eight notes or a pause; the take is logged as `c4-response`, never graded or scheduled; the feedback names strays, the pentatonic box and the bridge notes that turn it into the scale, and whether the phrase landed home; a Settings toggle, on by default; a row on Progress); Spanish on every remaining screen (the Mic lab, Progress, Keys including the why-it-works cards and the capo helper, Changes, Loops, Settings, the skill titles, the drill rationales, the session goal, the experiment labels; a test keeps every id-keyed string present in English and Spanish complete); eight tunings through GLead's own list in `core/tunings.ts` (FretFree's two first, then half and whole step down, drop C, DADGAD, open G, open D; CAGED zones stay standard only). **Remaining P1:** chord detection, real-song clips, sync.
- **Sprint 9** ✔ built 2026-10-24, from the curriculum (levels 4 and 6) and the pilot's needs rather than the P1 list: B9 progressions by ear (PRD B4's progression half: the cadence, then three or four chords from the common six of the mode, tonic first, named by numeral in order or by playing the roots; a sequence item like B4, feedback per slot, the progression replayed on a miss); approach and passing-note measurement on Changes (every landing records whether it was reached by step, leap or the same note, and the notes between it and the next change with how many stayed in key, on the `TrialEvent`, in the take table and on Progress; R5 §2 has the two measures); the cohort view on Progress (several exports at once: one row per participant with placement, skills at criterion, retests, transfer, hit rate and confirm share, and the experiment arms pooled with trial and participant counts, for pilot kit §4). **Not built after Sprint 9:** phrase building as a graded drill (level 5), learning a song by ear (level 6), chord detection.
- **Sprint 10** ✔ built 2026-10-24, curriculum levels 5 and 6: the Songs screen (four tunes written in scale degrees in `src/songs/catalogue.ts`, Ode to Joy, Twinkle, When the Saints and an original minor study, each in two-bar phrases with chords by beat; a phrase is learned in a practised key the app picks: the cadence, then the melody with its own rhythm, played back by pitch class in order, then the chords strummed for their lengths and named by numeral or root in order; every attempt is a `b10-songs` trial and the learned ticks are read back from the log; the whole tune plays at the end and the next visit is in another key); the Phrases rung on Changes (a chord tone counts only when reached by step, PRD C1's last step graded); a Progress row for song phrases. **Not built after Sprint 10:** chord detection, real-song clips, sync.
- **Sprint 11** ✔ built 2026-10-25: chord hearing (PRD §2's chroma approach, the last P1 item): a spectrum from an AnalyserNode on the microphone is folded into twelve pitch classes and matched to the 24 major and minor triads by cosine similarity, the confidence being the score scaled by the margin over the runner-up (so a single note is no chord); a chord holds 150 ms before it counts; GLead owns the microphone stream and hands the vendored pitch detector a clone through its injectable `globals`, so both hear the same input; a strummed chord answers B2 (`InputEvent.chord`, graded by `sameChord` against the key's diatonic chords, below the confirm threshold the learner confirms as with notes); a Settings toggle, off by default (experimental); the Mic lab gains a strummed-chord part (eight open chords) and a result row, so R2 measures it on real devices; a fake chord detector for the specs. Also found and fixed: the service worker was never registered (`injectRegister: false` with no `registerSW` call), so the installed app did not work offline; `useRegisterSW` now registers it and a toast offers Reload when a new build is ready. **Not built after Sprint 11:** real-song clips, sync.
- **Sprint 12** ✔ built 2026-10-25, hardening before the pilot: restore from an export (PRD D6 had export only; `importAll` merges by id, trials by `trialId`, sessions by `sessionId`, cards by item with the later review winning, retests by skill, delay and anchor, Mic lab runs by time, settings only onto a device with no data of its own, so running it twice adds nothing twice); storage persistence (the app asks the browser to keep its data once a session is saved, and Settings shows the answer and what the device holds); the guitar split asked for on 25 Oct (every skill says whether it `needsGuitar`; Today groups ear-only skills apart from ear-to-hand ones and a "Guitar: not now" switch, remembered in Settings, runs a tap-only session with no mic, no play-along and no call and response); the first RTL screen tests (Today, Settings, Progress, on a fresh in-memory database through `src/test/render.tsx`); and the heavier screens load lazily so the first paint on a phone is smaller. **Not built after Sprint 12:** real-song clips, sync.
- **Sprint 13** ✔ built 2026-10-25, closing two measurement loops: the B7 adaptive band in the plan (`bandDecision` on each skill's last twenty practice trials, FretFree's thresholds: under 75% the skill is held to reviews and the goal says so, over 92% it gets one more new item; the runner's fixed scope level stays, the band acts on what is dealt); the Mic lab's median latency can be adopted as this device's `micLatencyMs`, which the runner takes off response times and the Changes scorer uses for its window and offsets, instead of the vendored 150 ms; a Markdown pilot report downloadable from the cohort view; a volume slider. **Not built:** real-song clips, sync.

Definition of done per sprint: `pnpm verify` green; the sprint's drill playable in Chrome and Safari on a laptop and on one phone or tablet; trial events validated against the R5 schema once it exists.

## 6. iPhone first (added 2026-10-24)

The pilot runs on phones, so the build targets the iPhone before anything else: GitHub Pages deployment from `main` (base path `/GLead/`), installable from Safari with its own icons, a Playwright project at iPhone 15 width that fails on any horizontal overflow and runs a session, tables that scroll inside their box, and every microphone start inside the tap that asks for it (iOS grants it nowhere else). WebKit is not installed in the build environment, so the phone pass runs in Chromium at phone size; the first real-Safari run is still Frank's.
